# US-016: Review, PDF, and Paperless send flow

## User story

**As a** user who has scanned pages, **I want** review, PDF creation, and Paperless upload to be presented as one recoverable flow, **so that** I can fix obvious page issues and submit the correct document only once.

## Acceptance criteria

- The Review step shows scanned pages as a mobile single-column list and a desktop grid, with clear page numbering based on the current visible order.
- Each page preview exposes rotate and remove actions; removal requires inline confirmation, and visible pages are renumbered immediately after removal.
- If a page cannot be displayed or is missing, PDF creation is blocked until the page is removed or otherwise resolved, and the error explains that existing scanned pages remain available.
- The PDF step summarizes page count, scan quality information when available, and pending page edits before PDF creation.
- PDF creation has waiting, success, and failure states; success provides download, send-to-Paperless, and return-to-preview actions, while failure preserves scanned pages and offers retry or review.
- The Send step verifies Paperless connectivity and metadata availability before upload, then allows title, correspondent, document type, and tag selection according to the effective profile configuration.
- Paperless authentication, authorization, metadata-loading, upload-running, success, and retryable-failure states use user-friendly messages with technical details available on demand.
- The upload action is disabled while an upload is running and after Paperless has accepted the document, preventing duplicate submissions from repeated taps or reconnection.
- After successful upload, the UI shows the Paperless task or document handoff identifier when available and offers a new scan and PDF download without exposing private token or metadata internals.

## UI concept references

- Mobile and desktop page preview layouts.
- Rotate, remove, corrupt-page, and PDF-blocked states.
- PDF ready, running, success, and failure states.
- Paperless connection, metadata, upload, success, and retry states.

## Out of scope

- Full document archive browsing in Scan Bridge after upload.
- Editing OCR text, thumbnails generated by Paperless, or Paperless-side workflow assignment beyond metadata supported by current configuration.
